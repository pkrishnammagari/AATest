# Low-Level Architecture — FH AECB Analyzer screen

A quick reference that maps each label on the screen to its code, config and
payload source. The AI Analysis section is excluded.

**Columns:** *Renders* is the module that emits the label. *Logic* is where any
decision about the value is made. *Config* is the file or constant that drives it.
*Payload* is the array and field it reads.

### §01 tiles

Tiles sit on a six-column grid. Row one: Emirates ID, Passport, Phone (two columns each). Row two: E-mail and Latest address (three columns each). On windows 1510 px and wider (AI panel closed) the grid goes four across: E-mail moves up into row one and the address takes row two.

**Shared rules for the identity tiles.** The bureau sends one row per reporting provider, so the same value arrives many times. Rows are grouped by value (`derive/identity.dedupe()`). For document numbers, spellings that differ only in dashes, spaces or case count as one value; the most recently reported spelling is shown and the others are in its hover ("Also reported as: …"). Each value remembers every provider that reported it, with each provider's own latest `DateOfLastUpdate`. A `(Historical)` suffix on the type string marks one provider's copy of one spelling as superseded. **Current vs historical is decided per provider:** each provider's own latest report of the value is its verdict (a same-day tie counts as current), and the value is current if at least one provider's verdict is current. So one bank dropping or reformatting a number never makes another bank's current record stale. Values sort newest-updated first. The **newest current** value is the tile's headline. Its badge is the provider that reported it most recently, with the others behind "+N" (hover lists them, most recent first). Every other value folds behind a chevron: "N prior" when all are historical, "N more" otherwise, each flagged "Historical" or "Also current" with "provider · Mon YYYY": the most recent reporter and that provider's own update date. If only historical values exist, the newest is shown with a "Historical only" flag. "Not reported" when no row arrived.

## §03 Worst Statuses

Reads `contractsTotalSummary` and `summary` (first row of each), plus `contracts` and `contractsHistory` for the derived 36-month panel. A **half-width card** beside §02. Three panels side by side (stacked below 1180 px): FH policy assesses some employer segments over 24 months and some over 36, so both windows sit together, with the lifetime count. Status colours come from the bureau's severity ranks in `config/status_codes.json`: rank ≤ 60 red (severe), 65–95 amber (adverse), 100 green (normal); a status the config doesn't know is never coloured.
